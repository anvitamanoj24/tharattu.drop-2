# tharattu.drop()

> cry-aware cradle companion — ESP32 + INMP441 + Supabase Realtime

```
INMP441 mic
    ↓
ESP32 detects cry
    ├── Servo rocks cradle immediately (local, no latency)
    └── HTTP POST → Supabase baby_events
                        ↓
                 Supabase Realtime
                        ↓
                  index.html UI
                 (strobe + audio + alert)
```

---

## Hardware

| Part | Notes |
|---|---|
| ESP32 DevKit | any 38-pin variant |
| INMP441 I²S mic | WS→25, SD→33, SCK→26 |
| SG90 servo | signal→GPIO 27 |
| 16×2 I²C LCD | SDA→21, SCL→22, addr 0x27 (try 0x3F if blank) |
| Power | 5 V USB to ESP32; servo can share if draw is low |

## 1 — Supabase project

### 1a. Create the project

1. Go to [supabase.com](https://supabase.com) → **New project**
2. Note your **Project URL** and **anon/public key**  
   *(Project Settings → API — do **not** use the service_role key)*

### 1b. Create the table

Open **SQL Editor → New query** and run:

```sql
create table baby_events (
  id         bigint generated by default as identity primary key,
  event_type text        not null,
  created_at timestamptz default now()
);

alter table baby_events enable row level security;

create policy "Allow insert events"
  on baby_events for insert to anon
  with check (true);

create policy "Allow read events"
  on baby_events for select to anon
  using (true);
```

### 1c. Enable Realtime

**Database → Publications → supabase_realtime**  
Toggle `baby_events` to **on**.

## 2 — ESP32 sketch (`tharattu_drop.ino`)

### 2a. Arduino libraries needed

Install these via **Sketch → Include Library → Manage Libraries**:

| Library | Search term |
|---|---|
| LiquidCrystal I2C | `LiquidCrystal I2C` (Frank de Brabander) |
| ESP32Servo | `ESP32Servo` |
| ESP32 board package | Add `https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json` to Board Manager URLs, then install **esp32 by Espressif** |

`WiFi.h`, `HTTPClient.h`, `WebServer.h`, and `driver/i2s.h` are all bundled with the ESP32 board package.

### 2b. Fill in your credentials

Open `tharattu_drop.ino` and edit the four lines at the top:

```cpp
const char* WIFI_SSID      = "YOUR_WIFI_SSID";
const char* WIFI_PASSWORD  = "YOUR_WIFI_PASSWORD";
const char* SUPABASE_URL   = "https://YOUR_PROJECT.supabase.co";
const char* SUPABASE_ANON_KEY = "YOUR_ANON_KEY";
```

> The ESP32 needs an internet-connected network to reach Supabase.  
> A phone hotspot works well. The sketch connects with `WiFi.begin()`  
> instead of creating its own access point.

### 2c. Tuning

| Constant | Default | What it controls |
|---|---|---|
| `SOUND_THRESHOLD` | 800 | Minimum sound level to count as a cry |
| `CRY_COUNT_REQUIRED` | 5 | Consecutive loud frames before triggering |

Increase `SOUND_THRESHOLD` if the cradle triggers on normal room noise.

### 2d. Upload

Board: **ESP32 Dev Module** — Port: your COM/tty port — Upload speed: 115200

Open Serial Monitor at 115200 baud. You should see:

```
=== THARATTU.DROP() STARTING ===
Connecting to Wi-Fi: YourNetwork
WiFi connected!
IP: 192.168.x.x
Local UI : http://192.168.x.x
=== READY ===
Sound: 42
Sound: 38
...
```

## 3 — Separate UI (`index.html`)

### 3a. Fill in credentials

Open `index.html` and edit the two lines inside the `<script>` block:

```js
const SUPABASE_URL      = "https://YOUR_PROJECT.supabase.co";
const SUPABASE_ANON_KEY = "YOUR_ANON_KEY";
```

### 3b. Open the page

Just open `index.html` in any browser — no build step, no server needed.  
The page connects to Supabase Realtime over WebSocket and listens for new rows in `baby_events`.

The connection indicator in the top-right corner shows:

| Indicator | Meaning |
|---|---|
| 🟢 **Live** | Realtime channel subscribed — events will arrive instantly |
| ⚫ **No config** | Credentials not set yet — use Manual test button to preview UI |
| ⚫ **Disconnected** | WebSocket dropped — page will retry on reload |

### 3c. Enable audio (important on mobile)

Browsers block auto-play until the user interacts with the page.  
Tap **♪ Enable** once after opening the page. After that, the lullaby  
plays automatically whenever a cry event arrives.

## 4 — How a cry flows end-to-end

```
1. INMP441 picks up sound above SOUND_THRESHOLD
2. cryCount increments each loop() tick (~100 ms)
3. cryCount reaches CRY_COUNT_REQUIRED (≈ 0.5 s of sustained noise)
4. activateTharattu() fires:
      a. systemActive = true
      b. sendCryToSupabase() → POST /rest/v1/baby_events
      c. LCD shows "KUNJU KARAYUNNU!"
      d. Servo rocks left↔right for 15 seconds
      e. systemActive = false, cryCount = 0
5. Supabase receives the INSERT
6. Realtime pushes the event to all subscribed UI clients
7. index.html triggers:
      a. Strobe overlay
      b. Alert overlay ("Cry detected — rocking now")
      c. Lullaby audio (if enabled)
      d. Rocks-today counter increments
8. UI auto-resets after 15 s (matches servo window)
```

## 5 — Offline / degraded behaviour

| Condition | ESP32 | UI |
|---|---|---|
| No Wi-Fi | Servo still rocks; Supabase POST skipped with a Serial warning | — |
| Supabase down | Servo still rocks; POST returns non-201; Serial logs the code | Realtime reconnects automatically |
| UI has no credentials | — | Falls back gracefully; Manual test button still works |

The physical cradle response is always local and instant — Supabase is only the notification channel.

## 7 — Security notes

- The `anon` key is safe to embed in client-side code — it only has the permissions granted by your RLS policies (insert + select on `baby_events`).
- Never embed the `service_role` key in the ESP32 sketch or the HTML page.
- If you make this project public, rotate your anon key and tighten the RLS policies.
